# SEED calendar: official documentation and tutorial evidence

Native-game research: 24 October 2026. Guest implementation notes updated for runtime 0.6.0 on 25 October 2026. This is a reference for designing Flaxa's guest demo and its guidance. It does **not** establish that Flaxa implements these live SEED capabilities or has access to a real Seedling.

## Scope and confidence

The [official SEED site](https://seed.game/) links to the [Klang help center](https://klang-games.eu.theymes.com/hc/en/seed). Its seven public categories currently list 73 articles. I checked that complete article index and read 25 articles relevant to activities, needs, work, learning, access and social scheduling. There is no dedicated public Scheduler article in that index.

The help center's [knowledge-base introduction](https://klang-games.eu.theymes.com/hc/en/seed/articles/just-ask-how-to-find-information-in-this-knowledge-base-282) says its question assistant draws gameplay answers from the official SEED Game Manual. That article does not expose a direct manual link. No assistant-generated answer was used as evidence here, and no exhaustive priority catalog was found.

The help center is marked `noindex`; public HTML was read directly because web search/open could not retrieve it. Relevant article HTML carries publication timestamps from 20 July 2026, but no visible last-updated date. Treat these as current accessible help text, not proof that every sentence reflects the latest release. Specific conflicts with newer dated patch notes are listed below.

These dated changes qualify older help text: personal Deliver is superseded by Haul, and harvesting through a Schedule Zone does not require individual TODO entries. The job-seeking threshold is inconsistent across official pages. Prefer newer explicit release behavior, and flag unresolved differences rather than making them tool contracts.

Learning terminology also needs care: [March 2025 development notes](https://seed.game/news-from-avesta/patch-notes-march-2025-1-0) introduced writing schematic manuals at a Research Table and studying them through Direct Control at suitable furniture. That is historical evidence for a distinct schematic-learning activity, not proof of a current Scheduler priority named Study. Current help explicitly documents Practice Skill, skill books and Pursue Interest as described above.

## Practical real-game workflows

These are guidance assembled from the sources above, not an API specification or actions Flaxa can execute.

- **Plan resource work:** choose an accessible location or Schedule Zone; add a time block and the appropriate harvesting/work priorities. For machine production, configure its production task and stop condition first. Inspect materials, skills and blocked-priority reasons if nothing runs.
- **Protect care and work:** review existing shifts and social commitments, leave time for needs, then add personal blocks. Needs may interrupt work. Pausing the Scheduler is different from stopping world time.
- **Plan a visit or gathering:** check service hours, access and charges; choose an interval without conflicts. Treat invitations as pending until accepted. Inspect both calendars before promising a shared appointment.
- **Reuse a week:** save a preset only after reviewing the week; jobs and one-off appointments are excluded. Recheck conflicts when combining a preset with existing commitments.

## Implemented Flaxa guest contract

The executable contract is the current tool schema and simulator, not the full game documentation. Runtime 0.6.0 supports one synthetic Seedling, 20 activity types, five recipes, eight needs, skill XP, a fixture sprain, one paid job, stockpiles, equipment condition and a crop-growth loop. These are intentionally simplified simulations. Quantities, durations, skill formulas, recipe inputs/outputs, wage eligibility and recurrence rules are demo balancing rather than measured native-game rules.

The calendar supports `once`, `daily`, `weekdays` and `weekly`. Day 1 is Monday in the demo; weekly repeats are anchored to a block's start day. Blocks cannot overlap or cross midnight. A due block queues one action for the block duration. Production is one batch per action, not unlimited output for longer blocks. Queue capacity and prerequisites can prevent work, and earlier running work can delay it. Editing or deleting a recurring block affects its whole series; no per-occurrence exception is supported.

Browser tools read and mutate the open demo. Remote MCP tools transform a full explicitly supplied snapshot. Neither surface controls live SEED, creates a real job or appointment, saves presets, draws zones, schedules paid visits or runs while closed. Reloading or closing resets progress. Read `get_companion_capabilities` for the actual activity/recipe/event catalog and the platform-specific knowledge under `knowledge/platforms/chatgpt-plugin/` for implementation provenance.

## Still unverified from these references

- The complete current Scheduler priority/activity enumeration and per-priority parameters.
- Exact personal event recurrence options, weekday selection, recurrence end dates and occurrence-versus-series editing semantics. A weekly preset is evidence of a weekly schedule, not proof of a particular recurrence API.
- Minimum/maximum block duration, grid increment, overnight-block representation and maximum number of calendar blocks.
- Exact conflict resolution among personal blocks, jobs, appointments, autonomous needs, TODO entries and direct commands. Evidence confirms some precedence relationships, but not a complete ordering.
- Travel-time reservation, late arrival, whether work continues past the scheduled boundary, and whether an interrupted activity resumes.
- The calendar epoch and mapping of game-day boundaries to Earth timestamps. The introduction documents a duration factor of one game day per real hour, but not an absolute timestamp conversion or Flaxa's demo rate.
- Current public APIs for reading or changing live Seedling calendars. These sources document the game UI and behavior, not integration endpoints.

For Flaxa, keep a clear division between **implemented guest behavior**, **documented live-game behavior**, and **unverified behavior**. Do not invent tool capabilities from a generic activity name. The guest activity catalogue, recipes and recurrence rules are demo choices, not a complete representation of SEED.
