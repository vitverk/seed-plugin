# SEED client support

SEED uses authenticated Streamable HTTP at `https://mcp.flaxa.app/mcp`. Compatible clients can connect directly or install the repository plugin. OAuth sign-in and upstream permissions remain required.

The portable `mcp.json` and the compatibility `.mcp.json` are both URL-only and rely on the server's OAuth discovery and the host's authorization flow; these files are not assumed to merge. The canonical challenge offers all seven currently supported SEED scopes, and Codex also requests `offline_access`. Do not add scope fields or `extensions` to either file: Codex installs the plugin without its MCP server when `mcp.json` declares them. Requesting scopes does not grant them, and existing connections need explicit reauthorization to add permissions.

MCP Apps-capable hosts can display the full companion, focused widgets and character creator. Other clients can use the same data and documentation tools in text. Source and protocol checks do not prove UI rendering or model routing in a particular host.

Gemini CLI installs the repository root using `gemini-extension.json`, with extension and server name `seed`. Its `mcpServers.seed.httpUrl` points to the same canonical endpoint and relies on OAuth discovery. It bundles no skills, context file or hooks; guidance remains server-owned. Google's [extension reference](https://geminicli.com/docs/extensions/reference/) and [MCP configuration guide](https://geminicli.com/docs/tools/mcp-server/) document these formats.

The Gemini CLI package targets text-based tool and documentation use. Model access requires supported authentication, such as a Gemini API key or an eligible existing organizational entitlement. Google's [consumer deprecation notice](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals) confirms that personal Google sign-in, including Google AI Pro and Ultra, stopped serving Gemini CLI requests on 18 June 2026. This is separate from SEED authorization through `/mcp auth seed`.

Verified on 31 October 2026 with Gemini CLI 0.66.0: extension validation, local installation and listing passed in a temporary profile, which listed `seed` 3.4.0 as active with the canonical endpoint. Interactive Google OAuth completed, but model onboarding then rejected the personal account because that client is no longer supported for Gemini Code Assist for individuals. Authenticated SEED tool use remains unverified. The extension manifest does not install or configure consumer Gemini Connected Apps or establish MCP Apps rendering in Gemini web or Gemini Enterprise; those hosts require separate connection and rendering verification. See the [Gemini CLI quickstart](colleague-quickstart.md#gemini-cli).

Verified on 31 October 2026 with Antigravity CLI 1.4.12: `agy plugin import gemini` imported SEED 3.4.0, converted the endpoint to native `mcp_config.json` with `serverUrl`, and exposed the runtime server as `seed_seed`. Personal Google model sign-in and SEED OAuth through `/mcp` → **Authenticate** succeeded. A read-only grant excluded developer/gameplay writes; `my_account` with `part: "profile"` returned visible profile values, and saved SEED authorization survived fresh headless processes. See the [Antigravity CLI quickstart](colleague-quickstart.md#antigravity-cli).

Antigravity documentation navigation remains broken on the tested deployment: `search_seed_docs` succeeded but exposed only a count, without document links, and `read_seed_doc` with a verified URI succeeded but exposed only a receipt, without the document text. The missing data is in `structuredContent` without equivalent text content. This requires a server fix and retest; successful authorization and profile lookup do not establish full tool compatibility. Interactive-card rendering remains unverified.

Verified on 29 October 2026 with Claude Code 2.1.301: the Claude desktop app's Code tab rendered SEED's focused Seedling status card inline after a `seed@vitverk-seed` sign-in. The model receives only the card's JSON snapshot, so confirm rendering with the person viewing the session rather than from the tool result. A headless `claude -p` run advertised no MCP Apps capability, and Claude Code in a terminal shows text only. The full companion and character creator have not yet been checked in the Code tab.

SEED bundles no skills. Standard `search_seed_docs`, `read_seed_doc` and `seed://docs/index` discovery supply its guidance. Refresh metadata and begin a new chat after updating.

Existing OAuth aliases and internal identifiers remain compatibility details; user-facing presentation is SEED.

The server advertises the SEED S logo in its initialization metadata and on tools and resources, using the same-origin PNG at `https://mcp.flaxa.app/brand/seed-s-mark-v2.png`. MCP-capable clients choose how to display supplied icons. OpenAI UI entrypoints prefer tool icons; hosted app listings can instead use the app's registered logo. A custom app's listing logo may therefore need its own setting even when MCP icons are present. See the [MCP icon contract](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-11-25/basic/index.mdx#icons) and [OpenAI entrypoint icon precedence](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#entrypoint-icons).
